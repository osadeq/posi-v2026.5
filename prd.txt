# Projet : Generateur de Tests et Referentiels TOSA

## 1. Contexte et Objectif

Ce projet consiste à développer une application complète de gestion des tests de positionnement TOSA pour les formations bureautiques. Elle comprend deux modules :

- **Webapp Candidate** : Application stateless hébergée sur Vercel/Moodle
- **Dashboard Admin** : Application locale portable pour l'équipe pédagogique

## 3. Moteur IRT (Test Adaptatif)

### Principe
Le test adaptatif IRT (Item Response Theory) sélectionne chaque question en fonction du niveau de compétence estimé (theta) du candidat. Pour éviter les examens répétitifs, le moteur sélectionne aléatoirement la prochaine question parmi les 5 questions les plus pertinentes au niveau courant du candidat. Le test s'arrête quand la précision (SE) est suffisante ou après 30 questions. Le taux d'apprentissage (learning_rate) intègre un seuil plancher pour permettre aux candidats réalisant un sans-faute d'atteindre mathématiquement le niveau Expert (theta >= 1.0).

### Parametres IRT par question
```json
{
  "difficulty": 50,         // Difficulte (0-100). Conversion moteur : d = (difficulty - 50) / 10
  "discrimination": 1.0,   // Pouvoir discriminant (N1=1.2, N2=1.4, N3=1.6)
  "guessing": 0.25          // Probabilite de deviner juste (4 choix = 0.25)
}
```

### Calibrage IRT des questions (echelle theta)

La difficulte est calibree pour que chaque groupe de questions discrimine
au bon seuil de l'echelle theta unifiee :

| Niveau | Theta cible | Difficulty | Discrimination |
|--------|-------------|------------|----------------|
| N1 — Initiation | -1.2 a -0.4 | 38 → 46 | 1.2 |
| N2 — Intermediaire | -0.2 a +0.5 | 48 → 55 | 1.4 |
| N3 — Perfectionnement | +0.8 a +1.5 | 58 → 65 | 1.6 |

Gaps volontaires (46→48 et 55→58) pour creer des zones de discrimination
nettes aux seuils theta = -0.8, 0 et +1.

### Logique de positionnement (Regles metier)

#### Etape 1 : Declaration du niveau actuel
Le candidat declare son niveau actuel (sert uniquement a initialiser theta) :
- **Novice** : Je n'ai jamais utilise Excel → pas de test, EXCEL-INIT direct
- **Debutant** : Je connais les bases → theta_init = -0.5
- **Intermediaire** : Je maitrise les tableaux et formules simples → theta_init = +0.5
- **Perfectionnement** : Je maitrise les tableaux croises et fonctions avancees → theta_init = +1.5

#### Etape 2 : Test adaptatif (sauf Novice)
- **Novice** : Pas de test, programme direct = EXCEL-INIT
- **Debutant** : theta_init = -0.5, SE_init = 2.5
- **Intermediaire** : theta_init = +0.5, SE_init = 2.5
- **Perfectionnement** : theta_init = +1.5, SE_init = 2.5

#### Etape 3 : Determination du programme
A la fin du test (10 questions minimum, SE < 0.3 ou max 30), la regle est **unifiee** : theta seul determine le niveau actuel, puis le niveau actuel determine le programme.

| ThetaResult | Niveau actuel | Programme |
|-------------|---------------|-----------|
| theta < -0.8 | N0 — Novice | EXCEL-INIT |
| -0.8 <= theta < 0 | N1 — Debutant | EXCEL-INTER |
| 0 <= theta < 1 | N2 — Intermediaire | EXCEL-PERF |
| theta >= 1 | N3 — Avance | CERTIFICATION_TOSA_EXPERT |

**Cas special Novice** : oriente directement en EXCEL-INIT sans test.

**Note** : Le niveau declare sert uniquement a initialiser theta de depart. Le resultat final depend exclusivement de theta mesure par l'IRT.


## 4. Structure de la Base de Donnees

### 4.1 Referentiel TOSA (db/database.json)
- **Formations** : Excel, Word, PowerPoint...
- **Niveaux** : N1 (Initiation), N2 (Intermediaire), N3 (Perfectionnement)
- **Domaines** : ENV, CALCUL, MFORME, GDONNEES
- **Competences** : Codes Nx-DOMAINE-Cxx (ex: EXCEL-N1-ENV-C01)
- **Positionnements** : AutoPositionnement + TestPositionnement

### 4.2 Questions Externes (db/questions/)
Fichiers JSON separes pour chaque question (Banque enrichie de 111 questions couvrant tous les niveaux et tous les domaines) :
- id, competencesCibles, question, reponses, reponseCorrecte
- **Parametres IRT** : difficulty, discrimination, guessing

### 4.3 Programmes (db/programmes.json)
4 programmes de formation :
- EXCEL-ATELIER : Atelier tutore individualise
- EXCEL-INIT : Initiation
- EXCEL-INTER : Intermediaire
- EXCEL-PERF : Perfectionnement

### 4.4 Donnees Dashboard (dashboard/data/data.json)
Candidats, tests_recus, programmes_generes, config


## 5. Webapp Candidate

- `/api/answer` - Soumettre une reponse

### Caracteristiques
- Stateless (pas de stockage local des sessions longue durée)
- Hebergement Vercel/Moodle
- Test adaptatif IRT long (30 questions obligatoires pour laisser la chance d'atteindre le niveau Expert)
- Restitution visuelle et animée du positionnement via Chart.js (courbe d'évolution, KPIs de réussites).
- Auto-positionnement UX (accordéons, master switch, options condensées sur 1 ligne, 45€/h base tarifaire).
- Rapport Auto-Posi backend complet via module `rapport_builder` en sortie `Exemple_programme_candidat` JSON-like.
- Mode `Debug` intégré pour la QA.

## 9. Historique des versions

### v1.4 (27/03/2026)
- **Débridage du plafond de Score IRT** : Application d'un incrément minimum garanti (`learning_rate = max(0.1, ...)`) pour empêcher la certitude algorithmique d'interdire au candidat d'atteindre le niveau N3 (Avancé).
- **Tirage Aléatoire Pondéré** : Le moteur IRT choisit de manière aléatoire la prochaine question parmi le Top 5 des questions les plus pertinentes pour *theta* afin de rendre chaque test unique.
- **Base de 111 questions** : Intégration d'une banque Excel tierce. Tous les domaines TOSA et niveaux (N1, N2, N3) sont désormais exhaustivement couverts.

### v1.3 (26/03/2026)
- **Fiabilisation IRT** : Rapatriement de l'attribut `reponseCorrecte` dans la base de QCM en correspondance stricte sur les clés (`A`, `B`, `C`, `D`) pour un calcul de probabilité IRT sans faille.
- **Réécriture Experte** : Reformulation complète des 30 questions avec le jargon technique officiel et clarification des pièges. Correction des formules tronquées dans les JSON.
- **Allongement du test** : Fixation de `min_questions` à 30 et `min_se` à 0.0 pour laisser aux vrais experts l'opportunité mathématique d'atteindre un Theta >= 1.0.
- **Data Visualisation** : Remplacement des scores textuels bruts de Theta par une courbe `Chart.js` dynamique animée (points verts/rouges) s'alimentant depuis un `correct_history` backend.
- **Refonte UI Identification** : Retrait du champ de niveau déclaratif masqué, ajout du recueil des `objectifs`, et intégration de deux boutons directifs ("Novice" vs "Je passe le test").
- **QA** : Ajout d'un panneau `Mode Debug` affichant la solution et le feedback pédagogique en direct pour faciliter la qualification continue.

### v1.2 (25/03/2026)
